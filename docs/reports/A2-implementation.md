## Design decisions (for review)
1. **Transport**: plain `URL.openConnection(Proxy.NO_PROXY)` to `http://127.0.0.1:8765`. No Network binding or socket factory; NO_PROXY so a system proxy never sees the bearer. Connect 2 s, read 3 s, total call budget 5 s (worst case under the 10-s bridge deadline). No redirects (3xx gives `BAD_PAYLOAD`), no caches, `Accept-Encoding: identity`, and `Connection: close` (no pooled-socket silent POST retry that could burn a pairing attempt). Declared or streamed bodies over 256 KiB are rejected, as is a Content-Length mismatch (truncation). Errors become fixed codes; the exception carries no cause or message detail.
2. **Error mapping**: refused/IO gives `USB_UNAVAILABLE`; timeout/budget `REQUEST_TIMEOUT`; 5xx `HUB_UNAVAILABLE`; malformed/oversize/redirect/echo `BAD_PAYLOAD`. Link state: OK is `connected`, no result yet is `connecting`, `AUTH_REQUIRED`/`BAD_PAYLOAD` are `error`, and other codes are `disconnected`. Cancellation (`SESSION_ENDED`, e.g. renderer teardown interrupt) is not recorded as a link failure.
3. **Strict parsing**: UTF-8 decoding with REPORT, `StrictJson` (duplicate keys, trailing data, depth, nonfinite numbers), then `ProtocolValidator.hubSnapshot` (the D1 schema mirror). **Byte-safe redaction**: a payload containing the bearer is rejected whole, whether raw, case-changed or `\u`-escaped. The check is a case-insensitive byte search over the raw body and the re-serialized JSON.
4. **Cache/age**: `ageMs` is the monotonic time since receipt of that exact payload. Failures never touch the baseline; the wall clock is never consulted. `stale` is true when there is no data, age ≥ 6 s, or `AUTH_REQUIRED`. So a failure 3 s after a success shows `disconnected`, not stale, matching the PRD's "six seconds without a successful response". Empty cache gives null `ageMs`/`data`.
5. **Polling**: one snapshot flight. Concurrent callers join it, waiting up to 6 s, instead of opening another. Healthy minimum spacing is 1 s, so the JS 2-s start-to-start poll is never halved. Failure backoff is 1/2/4/8/15 s, capped. `resume()` (onStart) polls immediately; `pause()` (any non-approval stop, via `NativeSession.onBackground` and `onStop`) cancels/disconnects in-flight calls and discards their results by epoch; `close()` on onDestroy. Pair and snapshot have separate slots.
6. **Token**: `PrivatePairingStore` uses MODE_PRIVATE preferences (backup already disabled for every domain); `commit()` on set, so pairing reports success only once the token is durable. Only `LaptopClient` request construction reads it. A 401 clears the token (memory and store) **only** if the body is the hub's exact `{v:1,error:{code:"AUTH_REQUIRED"}}` and the rejected request used the current token. Other 401s and all network/5xx errors never erase it. After a 401, no further requests are made until explicit re-pairing.
7. **Pairing**: `app.setupHub` still acknowledges immediately (A1 `startSetup`). `onStartSetup` opens one native dialog (numeric, 8-char limit, autofill off, FLAG_SECURE, no state save). `HubPairingFlow` runs `pair()` on a one-thread pool that idles out, then posts the outcome. Expired/closed/persist-failed finish the setup as `failed(code)`. Wrong code or USB errors keep the dialog open (the hub's own 5 attempts govern). Malformed codes never reach the hub. Native 120-s expiry also dismisses the dialog via a delayed check. `NativeSession.paired` follows token presence. The pairing dialog is not an OS approval, so `beginOsApproval` is not used and a stop during code entry cancels setup (A1 semantics preserved).
8. **Late pairing token** (diverges from the draft): if the hub's 200 `{token}` was fully received, it is persisted even if a stop raced it. The hub has already rotated, so discarding it would orphan the pairing. A connection cancelled before the response yields nothing.
9. **Orientation (A1-R4)**: the manifest starts `sensorLandscape`, so a portrait-held phone still opens landscape. `OrientationPolicy` arms after a landscape reading (90°/270° ±30°). A continuous portrait hold (0°/180° ±30°) of 1.2 s then switches to `fullSensor` for the rest of that Activity, and the listener is disabled. Flat, unknown or diagonal readings reset the timer. Each new Activity starts landscape again. No bridge operations were added. `configChanges` prevents recreation on rotation.

## Known gaps / limitations
- The transport tests use the JDK `HttpURLConnection`. Android's OkHttp-based implementation (cancel via `disconnect()`, truncated-body behaviour, Host header `127.0.0.1:8765`) is device-unrun.
- Lint keeps 7 warnings, all A1-R5 categories: pinned SDK/AGP/Gradle/Gson notices; the `MissingOnRenderProcessGone` false positive; `DiscouragedApi` now on `sensorLandscape` (Android 16+ ignores fixed orientation only on large screens; not expected on the Redmi, but unverified). `ApplySharedPref` was fixed, not suppressed.
- Activity recreation for causes outside `configChanges` (for example uiMode/locale) recreates the client: empty cache, re-fetch, unfinished setup cancelled. Process death re-fetches by design.
- Dialog view code is covered only by the flow logic tests plus the unrun instrumentation. The D3 reverse launcher and the dashboard's handling of `AUTH_REQUIRED`/`connecting` were not exercised here.
- The preferences file is not separately encrypted (app sandbox, backup disabled). `clearToken` uses `apply()`; a lost clear costs one more bounded 401.
