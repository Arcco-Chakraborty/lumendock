## Review evidence

Inspected the C2 brief, approved design spec and implementation plan, frozen C1 schemas, C2 implementation report, snapshot-relative diff (`task-2-diff.md`), and current desktop source, test, and documentation files with line numbers:

- `desktop/src/calendar/connection.ts` (`1–52`) & `desktop/src/private-files.ts` (`1–40`):
  - **Atomic state replacement under lock (`connection.ts:27–51`, `private-files.ts:24–40`):** Every connection mutation (`beginConnect`, `finishConnect`, `saveTokens`, `applySelection`, `invalidate`, `disconnect`) executes inside `withLock(join(this.directory, 'connection.lock'), ...)` and replaces `connection.json`, `client.json`, and `tokens.json` via `atomicWrite` (`0600` temp file with `O_CREAT | O_EXCL | O_NOFOLLOW`, `fsyncSync`, `renameSync`, and parent directory `fsyncSync` on POSIX). Zero network I/O occurs inside any lock callback.
  - **Separate private token storage and Windows ACL enforcement (`connection.ts:12–19, 32`):** OAuth client config (`client.json`) and tokens (`tokens.json`) are stored separately from `connection.json` inside `calendar/`. On POSIX, directory mode `0700` and file mode `0600` with current-UID ownership checks are enforced. On Windows (`win32`), `prepare()` runs `protectWindowsDirectory` via PowerShell to set the current user SID as owner, enable access rule protection without inheritance, grant only current-user `FullControl` (`ContainerInherit,ObjectInherit`), and verify the resulting DACL before any file is written—failing closed with `CALENDAR_PRIVATE_STORAGE` if ACL protection cannot be established.
  - **Connection generations, selection revisions, and race-safe token persistence (`connection.ts:6, 29–51`):** `beginConnect()` installs a fresh random base64url `generation` and `selectionRevision` (`applied: false`, `connected: false`) and deletes prior credentials. `finishConnect()` verifies the generation still matches before writing credentials and flipping `connected: true`. `saveTokens(generation, tokens)` re-verifies `this.credentials(generation)` under lock, preserves existing `refreshToken` when omitted by token rotation (`tokens.refreshToken ?? credentials.tokens.refreshToken`), and returns `false` without recreating `tokens.json` if a concurrent `disconnect()` or reconnect changed the generation. `invalidate(generation)` transitions to a fresh disconnected generation with `authRequired: true` and deletes credentials.

- `desktop/src/calendar/oauth.ts` (`1–398`) & `desktop/src/calendar/cli.ts` (`1–140`):
  - **Fixed Google endpoints and Desktop client validation (`oauth.ts:9–10, 22–51`):** Uses fixed `GOOGLE_AUTH_URL` (`https://accounts.google.com/o/oauth2/v2/auth`) and `GOOGLE_TOKEN_URL` (`https://oauth2.googleapis.com/token`), ignoring any `auth_uri` or `token_uri` embedded in the client JSON file. Rejects `web`-only client files and non-ASCII/oversized client fields (`CALENDAR_CLIENT_INVALID`), and reads the client file via `readOwnedFile`.
  - **PKCE S256, `state`, ephemeral loopback listener, and exact 3 scopes (`oauth.ts:11–15, 53–56, 93–97, 129–309`):** Generates 32-byte base64url PKCE verifier + SHA-256 `S256` challenge and 24-byte random `state`. Binds an ephemeral HTTP server to `127.0.0.1:0`, checks `isLoopbackRemote(req.socket.remoteAddress)`, ignores unrelated paths such as `/favicon.ico` with `404` without aborting the flow, verifies `state`, requests `access_type=offline` and `prompt=consent`, and verifies all three read-only scopes (`calendar.events.readonly`, `calendar.calendarlist.readonly`, `calendar.calendars.readonly`) on both callback (when present) and token response (`CALENDAR_PARTIAL_GRANT`).
  - **Safe `invalid_grant` handling and secret-free error handling (`oauth.ts:318–398`, `cli.ts:107–139`):** `refreshCalendarTokens` invalidates the store generation (`authRequired: true`) and throws `CALENDAR_AUTH_REQUIRED` on HTTP 401/403, `invalid_grant`, `unauthorized_client`, or narrowed scopes. Neither `oauth.ts` nor `cli.ts` logs or echoes authorization codes, access/refresh tokens, client secrets, or raw upstream Google error text.
  - **CLI commands and `setup_required` messaging (`cli.ts:24–106`):** Implements `calendar connect --client FILE`, `calendar disconnect`, `calendar status`, and `calendar help`. Upon connect, instructs the user to open the Agenda tab on the phone, review the discovered calendars, and tap Apply before any events are loaded, rather than claiming events were already imported.

- `desktop/src/calendar/api.ts` (`1–694`):
  - **Full `calendarList` pagination and 100-source cap (`api.ts:307–372`):** Pages through `/users/me/calendarList` with `showHidden=true`, skips `deleted` entries, maps `accessRole` to `read | busy | unavailable`, extracts default reminder minutes, sanitizes email-like calendar summaries, and throws `CALENDAR_CAPACITY` if discovered sources exceed `MAX_SOURCES_CAPACITY` (100).
  - **Calendar label metadata discovery (`api.ts:373–446`):** Fetches `/calendars/{id}?fields=id,summary,timeZone,labelProperties` with `MAX_CONCURRENT_UPSTREAM = 2` for readable sources, parsing `labelProperties.eventLabels[]` (`id`, `name` bounded to 50 code points, hex `color`/`backgroundColor`). Non-401 metadata errors degrade gracefully (`labelMetadataAvailable = false`) without failing source enumeration.
  - **Bounded `events` pagination, DST-aware display-zone boundaries, and `eventLabelVersion=1` fallback (`api.ts:87–125, 562–694`):** Computes exact display-zone midnight boundaries via `zonedMidnightEpochMs` (two-pass `Intl.DateTimeFormat` offset calculation across DST transitions). Requests all pages with `singleEvents=true`, `showHiddenInvitations=true`, `showDeleted=false`, and no `eventTypes` filter. Opts in to `eventLabelVersion=1` and automatically falls back to standard event reads on HTTP `400` (`labelOptInFallback = true`).
  - **Event normalization, identity stripping, and upstream bounds (`api.ts:36–42, 127–234, 430–560, 623–685`):** Hashes calendar and event IDs into deterministic `[A-Za-z0-9_-]{1,80}` opaque IDs (`cal_...`, `evt_...`), strips organizer/attendee identities while extracting `selfResponseStatus` (`needsAction | declined | tentative | accepted | null`) from the `self: true` attendee, excludes `cancelled` events, normalizes empty titles to `"Untitled event"`, preserves date-only all-day moments (`start.date < end.date`) and timed moments with IANA time zones, resolves event labels separately from calendar badges (with legacy `colorId` fallback and no fabricated label names), enforces a 2 MiB (`MAX_UPSTREAM_RESPONSE_BYTES`) streaming response cap (`CALENDAR_CAPACITY`), and parses `Retry-After` seconds/HTTP-date headers.

- `desktop/src/calendar/service.ts` (`1–1349`):
  - **Opt-out startup and `setup_required` gate (`service.ts:271–323, 449–505, 901–983`):** Starts `disabled` when disconnected with zero network activity. On connect/reconnect, enters `setup_required` and queues metadata discovery only; readable sources default `selected: true` during `setup_required` (`service.ts:406`), and zero `/events` requests run until `select()` is applied. Newly discovered sources after initial `select()` default `selected: false`.
  - **Per-source complete replacement, independent metadata re-application, and mid-sync cancellation (`service.ts:325–398, 589–602, 758–838`):** Replaces a source's cached window only when all of its pages succeed; on per-source failure, retains that source's previous complete events and `lastSuccessAtEpochMs` and transitions the range to `partial` (`CALENDAR_UNAVAILABLE`). Metadata refresh re-applies updated calendar names/colors and label definitions to cached events via `reapplySourceMetadata`. Deselection or disconnect mid-sync invalidates cursors, removes deselected source windows, aborts in-flight requests on disconnect, and rejects late results via generation and `selectionRevision` checks.
  - **Range-global deterministic sort and whole-range `nextEvent` (`service.ts:46–113, 363, 1012`):** Sorts all range events by occurrence start in the display time zone (all-day events at display-zone midnight), then `sourceId`, then `id`. Computes `nextEvent` across the entire completed range cache (`rangeEntry.events`, even when >50 items exist), selecting only eligible timed events (`kind === 'time'`, `selfResponseStatus !== 'declined'`, `end.epochMs > serverNowEpochMs`) and ordering ongoing events (`start.epochMs <= serverNowEpochMs`) ahead of earliest future start with deterministic tie-breakers.
  - **Capacity, staging, cursor, and refresh bounds (`service.ts:32–44, 660–680, 703–708, 775–795, 841–871, 988–1156`):** Enforces 3 cached ranges / 16 MiB total cache (LRU eviction via `lastViewedAtMs`), 10,000 occurrences / 16 MiB per-range staging cap (preserving prior complete range data on `CALENDAR_CAPACITY`), 1 active + 1 latest pending range job, 50 items / 50 sources / 128 KiB serialized bytes per page, 10-minute cursor TTL bound to `rangeKey + revision + selectionRevision`, 15-second manual refresh coalescing (rotating `revision` immediately and queuing both metadata and event syncs), and 2-minute active / 15-minute idle periodic event refresh plus 15-minute metadata refresh honoring `backoffUntilMs`.
