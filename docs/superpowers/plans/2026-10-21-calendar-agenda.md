## Shared wire contract (freeze after C1)

Implement calendar domain schemas in `packages/protocol/src/calendar.ts`; no import from schema.ts back into calendar.ts. Existing schema.ts imports these schemas and composes link wrappers and three bridge operations. `index.ts` exports the calendar domain. Each listed object is strict; export corresponding inferred types. Use finite numbers/safe nonnegative integer epoch milliseconds, validated real Gregorian YYYY-MM-DD dates, Intl-validated IANA time zone strings (max80), opaque IDs max80 matching `[A-Za-z0-9_-]+`, colors `#RRGGBB`, bounded text by code points. Titles max256; source names max120; label names max50; cursors max256. Empty titles normalize to `Untitled event` rather than drop an event.

- `CalendarRangeRequestSchema` / `CalendarRangeRequest`: `{startDate, days, timeZone, cursor?:string, refresh?:boolean}`. Reject `refresh:true` together with a cursor. Explicit refresh invalidates the active range's next-page cursor and queues both event and calendar/label metadata refresh; normal polling does not. Coalesce repeated refreshes with a fifteen-second minimum spacing and honor longer upstream retry backoff.
- `CalendarSourcesRequestSchema`: `{cursor?:string}`.
- `CalendarSelectRequestSchema`: `{sourceIds:string[] (unique, max100), expectedRevision:string}`. The 100-source explicit capacity keeps this request within the existing 16 KiB bridge budget. Discovery beyond 100 sources must show capacity, not silently drop sources. The collection budget applies independently.
- `CalendarErrorCodeSchema`: `CALENDAR_AUTH_REQUIRED | CALENDAR_UNAVAILABLE | CALENDAR_CAPACITY | CALENDAR_CURSOR_EXPIRED | CALENDAR_SELECTION_CHANGED | CALENDAR_UNSUPPORTED` (nullable inside domain replies). Extend existing bridge ErrorCode enum to include these.
- `CalendarStateSchema`: `disabled | setup_required | loading | available | partial | auth_required | error | capacity`.
- `CalendarMomentSchema`: discriminated union `{kind:'date', date:string}` or `{kind:'time', epochMs:number, timeZone:string}`.
- `CalendarEventSchema` / `CalendarEvent`: `{id, sourceId, title, start:CalendarMoment, end:CalendarMoment, calendarName, calendarColor:string|null, label:{name:string|null,color:string}|null, eventType:string(max40), status:'confirmed'|'tentative', selfResponseStatus:'needsAction'|'declined'|'tentative'|'accepted'|null, reminderMinutes:number|null}`. Require matching start/end kinds and strictly positive duration. Reminder minutes range 0–40320. Do not forward cancelled rows.
- `CalendarSourceSchema` / `CalendarSource`: `{sourceId,name,color:string|null,selected:boolean,capability:'read'|'busy'|'unavailable',state:CalendarState,lastSuccessAtEpochMs:number|null,errorCode:CalendarErrorCode|null}`.
- `CalendarPageSchema` / `CalendarPage`: `{v:1,state,errorCode,serverNowEpochMs,range:{startDate,days,timeZone},revision:string,selectionRevision:string,lastSuccessAtEpochMs:number|null,sourceCount:number(max100),failedSourceCount:number(max100),sources:CalendarSource[](max50),items:CalendarEvent[](max50),nextEvent:CalendarEvent|null,nextCursor:string|null}`. Sources on an event page cover that page's source identities; full source enumeration uses its own route. Empty/error replies still carry the requested range, revision and empty arrays. Enforce 128 KiB serialized budget.
- `CalendarSourcesPageSchema` / `CalendarSourcesPage`: `{v:1,state,errorCode,serverNowEpochMs,selectionRevision,sources:CalendarSource[](max50),nextCursor:string|null}`; 128 KiB.
- `CalendarSelectReplySchema` / `CalendarSelectReply`: `{selectionRevision:string}`. Errors use existing transport/bridge envelope semantics and fixed code; selection success does not start a Google write.
- Bridge `hub.calendar` args = CalendarRangeRequest, reply = `LinkSnapshot<CalendarPage>`; `hub.calendarSources` args = CalendarSourcesRequest, reply = `LinkSnapshot<CalendarSourcesPage>`; `hub.calendarSelect` args = CalendarSelectRequest, reply = CalendarSelectReply. All are within existing reply size limits. Domain cursor failures have safe fixed errors, no Google payload text.
- Matching desktop paths: POST `/v1/calendar/read`, POST `/v1/calendar/sources`, POST `/v1/calendar/select`. Exact args as JSON body, bearer required; responses raw respective domain type. No changes to GET `/v1/snapshot`.

All event pages use one deterministic range-global sort by occurrence start (all-day dates interpreted only for ordering at midnight in the requested display zone), then opaque source ID, then event ID. Compute `nextEvent` across the entire completed range cache, independent of loaded page: eligible timed events are not self-declined and end after serverNow, ordered ongoing first then earliest future start with deterministic ties. No all-day item is a timed Next up. Every page repeats the same range-global summary; its inline fields are enough to render it without an additional source table entry. Partial/stale source state remains visible; do not imply complete freshness.

Connection state is shared between CLI and hub in an atomically replaced app-owned private state file with a random connection generation and selection revision. Store tokens separately. Connect/reconnect installs a new generation under the existing app's file-lock mechanism and enters `setup_required`; it performs source/metadata enumeration only. The Agenda setup state opens the calendar-inclusion sheet, defaulting initially readable sources on. **No event request runs until the human reviews and applies that list through calendarSelect.** CLI success instructs the human to open Agenda and choose calendars, rather than claiming events are already imported. Future new sources default off. Reconnect clears earlier cache and requires the same confirmation sequence.

The running service checks connection state on every calendar read/source/select and at most every two seconds while it owns pending work. Connect/disconnect changes become visible without restarting the live hub. Disconnect first atomically installs a fresh disconnected generation under lock, then deletes credentials/preferences; it cancels jobs and clears cache. Every API/refresh result checks generation before publication. Persist refreshed tokens under lock only if the on-disk connection generation still matches the one that began refresh; late work cannot recreate credentials after disconnect/reconnect. Tests use two store instances sharing a temp directory to model separate processes. No network operation occurs while holding the file lock.
